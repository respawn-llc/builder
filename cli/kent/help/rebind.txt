Usage of kent rebind:
  kent rebind [--session <session-id>] [--project <project-id>] [--json] <path>

Schedule a Session move to an existing Workspace root.

Inside a Kent agent shell, the current Session is selected by default.
--session overrides that default and is required outside Kent shell commands.

Without --project, the Session stays in its source Project and Kent attaches an
unbound target path to that Project. If the path belongs only to another Project,
Kent prints complete commands for moving the Session or attaching the path to
the source Project.

--project moves the Session to that Project. Kent attaches an unbound target
Workspace automatically.

Kent acknowledges the scheduled move without waiting for an active Agent Step.
Session-owned background commands do not block the move and continue in the
directories where they started. Workflow-owned Sessions cannot move across
Projects. Enter or leave Kent Worktrees with the worktree command rather than
rebind.

Examples:
  kent rebind ../moved-workspace
  kent rebind --session <session-id> ../moved-workspace
  kent rebind --session <session-id> --project <project-id> --json ../other-project
