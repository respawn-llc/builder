Usage of kent task:
  kent task create --title <title> (--body <body>|--body-file <path>) [--workflow <workflow>] [--project <project>] [--source-url <url>] [--source-workspace <id-or-path>] [--json]
  kent task edit <short-id-or-task-id> [--title <title>] [--body <body>|--body-file <path>] [--source-workspace <id-or-path>] [--project <project>] [--json]
  kent task start <short-id-or-task-id> [--project <project>] [--execution-target <none|head|default_branch|custom_ref> [--custom-ref <ref>]] [--json]
  kent task resume <short-id-or-task-id>
  kent task approve <transition-id> [--execution-target <none|head|default_branch|custom_ref> [--custom-ref <ref>]]
  kent task move <short-id-or-task-id> <target-node-id> [--output name=value] [--execution-target <none|head|default_branch|custom_ref> [--custom-ref <ref>]]
  kent task complete [--transition <id>] [--commentary <text>] [--param name=value] [--<parameter> <value>] [--json <payload>|--json-file <path>] [--run <run-id>|--session <session-id>|--task <task-id-or-short-id> [--project <project>]] [--force]
  kent task list [--project <project>] [--workflow <uuid>] [--status <status>[,<status>...]] [--attention <attention>[,<attention>...]] [--column <key>[,<key>...]] [--sort <field:asc|desc>[,...]] [--page-size <n>] [--page-token <token>] [--json]
  kent task show <short-id-or-task-id> [--json]
  kent task cancel <short-id-or-task-id> [--reason <text>]
  kent task delete <short-id-or-task-id>
  kent task comment add <short-id-or-task-id> (--body <text>|--body-file <path>) [--author <user|agent>] [--author-id <id>]
  kent task comment list <short-id-or-task-id> [--page-size <n>] [--page-token <token>]
  kent task comment replace <comment-id> --body <text>
  kent task comment delete <comment-id>
  kent task comments <add|list|replace|delete> ... (alias of kent task comment)

What This Does:
  Manage workflow tasks and comments through the Kent server API.
  Agents can complete their current workflow node with kent task complete from a shell command.
  Agents can start an authorized task with kent task start.
  Outside Kent agent sessions, task completion requires --force plus one explicit selector.
  Short ids are resolved within the current project by default.
  task start accepts one concrete --execution-target as a deliberate override of a fixed workflow policy. Move and approval use it only to retry a server-required selection. custom_ref requires --custom-ref.
  task start --json writes one initiating-action object to stdout and no stderr: started exits 0, selection_required exits 3, and in_progress exits 4.
  kent task list resolves one active project/workflow link. Supply either scope only when its active link is unique, or supply both to select an exact link. --status filters the primary task status, --attention filters current question, approval, or interruption attention, and --column filters workflow columns. Sort by created, updated, status, column, run_count, or title. The default sort is status:asc,updated:desc.
