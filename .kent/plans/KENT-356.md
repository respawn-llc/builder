## Design

- The sidebar presents one bounded navigation stack.
- Opening a root destination starts a new stack and replaces any older root stack.
- Selecting a related Task pushes its Task Detail.
- Selecting a Task that already appears earlier returns to that retained destination and removes every later destination.
- Returning to an earlier Task silently discards unsent input retained by removed later destinations.
- Dependency Add pushes the ordinary New Task form with its originating relationship preconfigured and hidden.
- Inbox Previous and Next replace the current Inbox Task and do not add history.
- X closes the complete stack.
- Back returns to the preceding destination.
- Back at the root closes the sidebar.
- Back is hidden at the root.
- The header keeps X before Back and uses the existing icon-control presentation.
- The stack has no Forward action.
- The stack retains at most 50 destinations.
- Pushing a 51st destination preserves the root and silently evicts the oldest non-root destination and its retained interface state.
- Only the current destination remains mounted and live.
- Earlier destinations retain only bounded interface state. They do not keep loading, observing, subscribing, or extending query lifetime.
- Ordinary inactive Task Detail queries keep the app's existing time-based cache behavior.
- Back restores scroll position, description expansion, the selected Comments or Activity tab, unsent Task title/body edits, unsent new-comment text, and one edited-comment draft.
- Back does not restore unfinished Question responses, server projections, query pages, loading state, mutation state, or subscriptions.
- Restored Task Detail refreshes server-authoritative data and layers retained unsent Task/comment drafts over it.
- An incoming focus request applies only when that Task destination is first opened. Back restores the saved viewport without replaying the original focus request.
- Scroll restoration creates one typed pixel-offset request with a distinct request key after refreshed rows mount. `VirtualizedInfiniteList` applies each request once through TanStack Virtual, renders the range at the nearest available position, and lets ordinary edge-driven load-more run from that restored range. It does not load pages only to reconstruct an old viewport.
- A current Task Detail that receives a typed missing-Task result immediately goes Back without showing stale Task content.
- A current Project Edit that receives the typed Project-missing result immediately goes Back instead of retaining Retry forever.
- Every other Project-bound sidebar destination owns the same behavior when one of its required Project reads or mutations returns the typed Project-missing result. The implementation audit covers New Task, Project-linked Workflow Create, Link Workflow, and project-scoped Workflow Editor; destinations with no Project requirement remain unaffected.
- If a missing Task- or Project-bound destination is the root, its Back closes the sidebar.
- If Back reveals another missing destination, that destination performs the same check and goes Back again. This lazily skips missing retained destinations without a history scan.
- Missing-destination Back does not wait for restored data or a retained-state snapshot. Back discards the missing current destination, so it captures nothing.
- Task and Project deletion do not otherwise alter sidebar history. The sidebar receives no deletion event and knows no Task or Project identity.
- Leaving the Desktop screen that owns a root sidebar closes that root stack unless another root sidebar has already replaced it.
- Opening an unrelated root sidebar replaces the prior stack. Cleanup belonging to the prior screen cannot close the replacement.
- Once Push, replace, Back, close, or root replacement is accepted, completion from the outgoing destination cannot change the accepted stack even before the UI rerenders or unmounts that destination.
- Every destination-originated close or successful completion is scoped to that destination's mounted-page capability. A stale ordinary New Task, Workflow Create, Link Workflow, Workflow Inspector, Task/Project missing, or Pop-out callback cannot settle, close, or otherwise mutate a replacing root or its pending result.
- Browser URL text and browser-history behavior are not part of the Desktop product contract.
- Related-Task selection and Dependency Add remain unavailable while the current Task title/body or add/edit-comment save is pending. Relationship Remove keeps its existing independent availability.
- Leaving a Task Detail while one of its saves is pending uses the ordinary discard/close behavior. Later settlement does not restore or reopen it.
- New Task has no Cancel button and does not show Dependencies.
- Before submission starts, Back from New Task discards the form and restores the preceding destination, and X discards it and closes the stack.
- Unsubmitted New Task Back does not require a snapshot because the discarded form is not reachable through Forward.
- Only while a related New Task request is pending, header Back and X are unavailable. Ordinary New Task never acquires this pending-exit lock.
- Related New Task atomically creates the Task and relationship.
- Current success replaces New Task with the created Task Detail and leaves the originating Task directly behind it.
- Current failure releases the related pending-exit lock and preserves the ordinary New Task recovery path.
- Screen change or root replacement remains legal while related creation is pending. If success or failure arrives after that replacement, the Task and relationship outcome remains authoritative and the replacement sidebar does not change.
- Pop out opens only the current Task Detail.
- Current pop-out success closes the originating stack after the separate window opens.
- Pop-out success after that destination or root stack was replaced leaves the separate window open and does not close the replacement.
- Pop out and X keep the approved silent-discard behavior for unsent input.
- Disconnect and reconnect preserve the stack and retained interface state. The current destination uses its ordinary reconnect and refresh behavior.
- Push and Back use a quick horizontal transition and respect reduced-motion settings. X keeps the existing whole-sidebar close transition.
- KENT-356 does not add browser-route migration, server/worktree changes, test timeout changes, query-cache ownership, existing-Task dependency search, or Task upsert.

## Architecture

- Treat merge-base `c945238c9` as the implementation starting point. Do not recover the superseded provider, TanStack-history wrapper, destination membership fields, deletion coordinator, route-transition owner, route test harness, scoped admission state machine, or history-wide invalidation code from branch history.
- Keep `SidebarProvider` generic. It owns one immutable in-memory stack of generic destinations and retained snapshots, the existing pending root result, width profiles, and presentation phase. It imports no Task, Project, Board, Workflow, query, mutation, deletion, or router feature module.
- Implement only four generic stack commands: Push, replace current, Back, and close. Back at root delegates to close. Push performs branch truncation, injected equality-based return-to-earlier, and root-preserving capacity eviction in one state transition.
- Keep feature equality outside sidebar code. App composition supplies one typed destination policy that can compare destinations and narrow retained snapshots. The generic stack consumes that policy without inspecting destination variants or strings.
- Keep stack positions, private remount mechanics, and one current-page registration private to the provider. The generic page host creates the registration immediately when it mounts, before destination data is ready. It contains one private mutable capability cell, header Back/X availability, an optional capture slot, and capability-scoped page operations including close and typed root completion. No lifecycle, entry, activation, route, deletion, or operation identifier/token appears in app-facade or feature contracts.
- Separate navigation capability from retained-state capture. Back/X availability controls only the rendered header controls; it does not delay navigator creation or block destination-owned missing Back. Task Detail installs the optional capture slot only after restored data is ready. Destinations such as missing Task/Project and unsubmitted New Task can navigate Back while the slot is absent.
- Determine the generic transition shape before changing currentness. An append Push retains the outgoing entry and therefore must synchronously resolve a present capture slot first; if capture is absent or unavailable, reject Push with the capability still active. Once append Push is accepted, revoke the outgoing capability and commit its captured snapshot plus the new entry. Same-destination return-to-earlier, replace, Back, close, and root replacement discard the outgoing page, so they synchronously revoke and commit without capture.
- Give the mounted page a navigator whose Push, replace, Back, close, and `complete(result)` methods read that private capability cell. `complete` is typed root-result settlement plus close/root teardown, not a fifth history operation; it revokes synchronously, settles only the root that owns the current page, and begins the existing close presentation. Accepted generic transitions and root teardown are the only semantic writers that change the cell from active to revoked. Registration setup never writes an existing cell back to active. React effect cleanup never revokes the cell; it may compare-and-clear only its own capture/availability registration, and replay setup reinstalls that registration without changing capability state. A newly mounted component instance, including A after A→B→A, creates a fresh active cell. Do not add IDs, epochs, revisions, cancellation signals, owner objects, or conditional-current method families.
- Require every page-host removal that can leave `SidebarProvider` alive to result from an accepted generic transition/root teardown, which has already revoked the outgoing cell. Whole-provider/app unmount leaves no surviving stack owner and does not use page effect cleanup as a semantic transition.
- Keep asynchronous ownership in destinations. Related New Task uses scoped replace; ordinary root New Task uses scoped typed completion; Workflow Create and Link Workflow use scoped typed completion and perform their existing follow-up navigation only when completion is accepted; Workflow Inspector missing-node uses scoped close; Pop out uses scoped close; Task Detail, Project Edit, and audited Project-bound destinations use scoped Back after the applicable typed missing result. The provider does not know which asynchronous operation produced a page operation.
- Add one generic root-lifecycle capability for screen owners. Opening a root returns a release function scoped to that root. A screen releases its root on selector change or unmount. The release becomes inert after another root replaces it. There is no router subscription, pathname/search observer, route cause, deferred reconciliation, or browser-history test contract.
- Split authority by caller. Screen code receives root open/release. Shell code receives current X, phase, and sizing. `SidebarDestinationView` and feature destinations receive only the mounted-page navigator. Provider-global `resolveSidebar` or `closeSidebar` must not be passed into destination dispatch or exported as page-facing authority.
- Board selected-Task opening uses the generic root lifecycle only. Task deletion mutation and project subscription paths do not call sidebar code. Removing every selected-Task deletion hook/coordinator is required.
- AppChrome and Project deletion do not inspect or mutate stack entries. Visible screen navigation releases the screen-owned root through the ordinary generic lifecycle. Project Edit handles `ErrCodeProjectNotFound` through a typed Desktop API discriminator and generic Back. Audit New Task, Project-linked Workflow Create, Link Workflow, and project-scoped Workflow Editor at their existing Project query/mutation owners and apply the same destination-owned Back only when their required Project operation returns that discriminator; never parse error text.
- Task Detail owns one compact retained-state model and decoder. Reuse the existing local state owners and expose one capture function rather than duplicating each field in provider state. Its navigator registration is active immediately; apply restored state once per mount, then install the capture slot so append Push cannot retain pre-restoration defaults.
- Task Detail handles only the typed missing-Task discriminator. Other load failures keep the existing Retry behavior. Missing handling calls generic Back; it does not publish deletion or Project information.
- Add the missing narrow `VirtualizedInfiniteList` pixel-offset request API. The typed request contains a destination-local request key and non-negative pixel offset. The list remembers only the last applied key, waits for its scroll element and refreshed loaded rows, calls TanStack Virtual `scrollToOffset` once per key, and accepts the virtualizer's nearest loaded position. Its existing visible-range load-more logic may run from that restored range, but restoration never requests pages merely to make a deeper offset attainable.
- Related Task rows and Dependency Add receive the mounted generic navigator only inside sidebar Task Detail. Standalone Task Detail keeps its existing main-screen navigation.
- New Task keeps the existing `pendingRelationship` and atomic server mutation. The destination supplies `backAvailable` and `closeAvailable` as false exactly when `pendingRelationship !== undefined && createTask.isPending`; pre-submission and ordinary New Task keep both controls available. Current failure naturally re-enables them when mutation pending state settles. Root/screen replacement bypasses only these header controls, remains legal, and synchronously revokes the outgoing form navigator before later settlement can navigate. Do not add provider-owned admission, settlement, or mutation state.
- Keep native pop-out payload unchanged. Its destination-owned completion calls generic close and relies on synchronous navigator revocation when another navigation/root replacement is accepted, not on a later React unmount.
- Delete the route/deletion implementation and tests instead of adapting them. Replace the 599-line route test file with focused root-owner tests for mount, selected root change, unmount, and stale release after replacement. Do not assert URL strings, browser Back/Forward, effect order, or route table internals.
- Update the Desktop specification in product language. Remove browser URL/history requirements and proactive Task/Project history reconciliation. State destination-owned typed missing handling, lazy skipping, root Back closure, root replacement, and screen-owner release.
- Production budget: generic stack/provider/current host including scoped completion 270–340 LoC; shell Back/motion 70–100; typed destination policy and root lifecycle integration 90–130; Task Detail retention/missing handling 200–250; virtualizer-owned pixel restoration 35–55; destination-owned Project missing handling 35–60; related traversal/New Task/Pop out 130–180; Workflow/New Task/Inspector settlement audit 35–60; styles/i18n and remaining caller cleanup 20–40. Target 880–1,175 LoC. The 1,200-LoC hard stop includes all production additions and modifications from merge-base.
- Test budget: generic stack/provider 250–340 LoC; Task Detail/traversal 210–290; virtualizer restoration 80–120; New Task/Pop out/root ownership 220–300; Workflow/Inspector settlement audit 100–160; Project missing handling 70–120; architecture/scope guards 50–80. Target 900–1,200 LoC.
- Architecture guards fail if sidebar code imports feature/router modules, if Task/Project deletion reaches a sidebar contract, if browser URL/history appears in product tests, if inactive entries are scanned on deletion, if Project missing is detected through error text, if DOM `scrollTop` is the sole virtualizer restoration authority, if Back/replace/close/root replacement requires capture, if append Push revokes before resolving capture, if an accepted transition schedules state before revoking the outgoing capability, if effect cleanup revokes capability or setup reactivates an existing cell, if a live-provider host removal bypasses an accepted transition, if destination/page code receives provider-global close/resolve authority, if stale completion can settle a replacement root result, if stale-completion IDs/tokens return, or if the final production diff exceeds 1,200 LoC.
